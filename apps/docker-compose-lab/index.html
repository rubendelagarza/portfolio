Lab: Compose stack, networking and startup order

A four-service Docker Compose stack (nginx, API, database, Redis) works on the developer's laptop but returns 502 on the server. Bring it up, read the logs, fix how the services find each other and the order they start in, and verify end to end.

Intermediate~12 mindocker compose · networks · healthchecks3 randomized stacks
What this demonstrates: container-to-container networking (service names, not localhost), Compose networks, published vs internal ports, healthchecks with depends_on: condition: service_healthy, and keeping secrets out of the compose file with .env.

Ticket INC-21177

Server shop01, project in /srv/shop. Edit files with nano; after a change run docker compose up -d again.

Objectives

    Containers on shop01

    How the stack is meant to work

    • web (nginx) is the only service published to the host, on port 80, and proxies /api/ to api:3000.
    • api needs db and cache, and connects once at startup (no retries).
    • The database must not be reachable from outside the server.
