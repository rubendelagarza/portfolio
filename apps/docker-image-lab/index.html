Lab: Slim down a 1.2 GB Docker image

The team's API image is over a gigabyte: CI is slow and the registry bill keeps growing. Measure where the size comes from, add a .dockerignore, rewrite the Dockerfile as a multi-stage build and ship an image under 200 MB that still works.

Intermediate~15 mindocker · Dockerfile · multi-stage3 randomized apps (Python, Node, Go)
What this demonstrates: reading docker history to find what makes an image big, build context hygiene, multi-stage builds, choosing a runtime base image (slim, alpine, distroless, scratch) and the runtime surprises each one brings: native libraries, static binaries and CA certificates.

Work order

You're on the build server build01 as ruben. The project is in ~/shopapi; files open in the editor with nano.

Objectives

    Docker on build01

    Requirements

    • Tag the new image shopapi:2.0.
    • Final image under 200 MB.
    • The app listens on port 8080 and must answer GET /health with 200.
    • Keep the Dockerfile multi-stage: build tools never ship in the final image.
