Lab: Container won't start (permissions and volumes)

Security hardened the notes service so it no longer runs as root. Since the deploy, the container restarts in a loop. Find out which user the container runs as and what it can't write to, then fix it the right way: no chmod 777, no running as root.

Intermediate~10 mindocker · volumes · UIDs3 randomized causes
What this demonstrates: troubleshooting a crash-looping container with docker logs and docker inspect, how UIDs map between a container and the host, the difference between bind mounts and named volumes, fixing ownership in a Dockerfile, and resisting the quick fixes that undo the hardening.

Ticket INC-20931

"Notes is down since this morning's deploy. The deploy only changed the image so it runs as a dedicated user (app, UID 10001) instead of root, as the security audit asked."

Server app02. Deploy files are in /srv/notes (run.sh, README.md, src/).

Objectives

    Docker on app02

    Rules

    • The container must keep running as UID 10001.
    • No world-writable directories (chmod 777, o+w).
    • No --user root and no --privileged.
    • Data must live outside the container so it survives re-creating it.

    Breaking a rule still lets the service start, but costs 25 points each.
