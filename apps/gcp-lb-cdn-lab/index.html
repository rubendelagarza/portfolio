Lab: Put a web app behind a global load balancer with Cloud CDN

Build a global external Application Load Balancer from its parts in Cloud Shell: health check, backend service, URL map, managed certificate, HTTPS proxy and forwarding rule. Then pick the right CDN cache mode and size Cloud NAT for a batch fleet.

Intermediate–Advanced~12 mingcloud3 randomized environments
What this demonstrates: configuring Google Cloud managed network services (Cloud Load Balancing, Cloud CDN and Cloud NAT) to improve performance and availability, and knowing the details that make them work, like health-check source ranges and port budgets.

Load balancer chain

Client brief: Contoso Shop

The storefront runs on managed instance group web-mig. Put it behind a global HTTPS load balancer on https://shop.contoso.com, with a Google-managed certificate and Cloud CDN.

Project
contoso-web
Network
web-vpc
Backends
web-mig · us-central1-a · 3 VMs · tag web · named port http:80
Reserved IP
web-ip (global) · DNS for shop.contoso.com already points to it

App notes from the dev team

  • Listens on HTTP port 80.
  • GET / returns a 302 redirect to /store.
  • GET /healthz returns 200 "ok" when the instance is healthy.
  • Static assets live under /static/. /cart is personalized per session.
  • The app does not send Cache-Control headers.

Objectives

    Bonus brief: batch egress

    batch-mig (300 VMs, subnet batch-subnet, us-central1) calls a partner API at one IP on port 443 and needs up to 2,000 concurrent connections per VM. The partner allowlists source IPs, so egress must use the pre-reserved addresses nat-ip-1 … nat-ip-12.
