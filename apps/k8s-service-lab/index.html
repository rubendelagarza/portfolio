Lab: Kubernetes Service with no traffic

After a rollout, the storefront gets errors calling orders-api, even though every pod is Running and Ready. Test from inside the cluster, follow the path Service → Endpoints → Pods, and fix it without opening the API to namespaces that shouldn't reach it.

Intermediate~12 minkubectl · Services · Endpoints · NetworkPolicy3 randomized faults
What this demonstrates: how a Service finds its pods (label selectors, Endpoints, port vs targetPort), testing with a throwaway pod, reading "connection refused" vs "timeout", and NetworkPolicies with namespace selectors, keeping least privilege while restoring traffic.

Ticket INC-21240

Jump host with kubectl on cluster prod-mx. Manifests in ~/k8s: change them with nano and kubectl apply -f.

Objectives

    namespace orders

    Security requirement

    Only workloads in the frontend namespace may call orders-api. Other namespaces (for example marketing) must stay blocked.
