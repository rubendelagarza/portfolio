Lab: Deploy a web app on a Linux server

A fresh Ubuntu server and an app in /opt/shopapp. Install nginx, lock the server down with a firewall, run the app as a proper systemd service under its own user, and publish it through an nginx reverse proxy.

Intermediate~12 minbash · nginx · systemd · ufw3 randomized serversPart 1 of 3
What this demonstrates: Linux server administration for hosting a site: package management, firewalling without locking yourself out, least-privilege service accounts, systemd units and nginx reverse proxying. Part 1 of a three-lab series (next: Cloudflare SSL, then SQLite and Google sign-in).

Work order

Contoso Shop's new VPS (web01, 203.0.113.50, Ubuntu 24.04) is ready, and DNS for app.example-shop.com already points to it. You're connected over SSH as ruben (sudo rights) from your laptop at 198.51.100.23.

Read /opt/shopapp/README.md for how the app runs.

Objectives

    Requirements

    • Public ports: SSH (22), HTTP (80), HTTPS (443). Everything else denied.
    • The app must not run as root. Use a dedicated system user called shopapp with no login shell.
    • The systemd service must be called shopapp and start at boot.
    • The app listens on localhost only; nginx is the only public entry point.
