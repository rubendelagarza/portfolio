Lab: Fix a remote user's VPN access

The VPN client says "Connected", but the intranet won't load. You have an admin command prompt on the user's laptop. Find the fault with real Windows tooling and fix it properly.

Intermediate~8 minWindows command prompt3 randomized faults
What this demonstrates: the structured triage I ran as a First Line Engineer at Atos and Webhelp and as an escalation point at TCS: gather evidence, split DNS from routing, fix the root cause, verify.

Ticket INC0048213

Maria Torres (Finance) is working from home. The GlobalConnect VPN client shows Connected, but she can't open the intranet (intranet.contoso.local) or the finance share (\\fs01.contoso.local\finance). Public websites load fine.

You're in a remote admin session on her laptop.

Objectives

    Network runbook

    VPN client pool
    10.200.0.0/24
    Tunnel gateway
    10.200.0.1
    Corporate range
    10.10.0.0/16 (split tunnel: only this goes through the VPN)
    Internal DNS
    10.10.0.10, 10.10.0.11 (pushed by the VPN via DHCP)
    intranet
    intranet.contoso.local = 10.10.1.25
    file server
    fs01.contoso.local = 10.10.2.40
    Split-tunnel route
    Created by the deployment script as a persistent static route
